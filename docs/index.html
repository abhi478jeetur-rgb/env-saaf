The bugs it kills

Every process.env value is a string. That one fact causes the same production bugs again and again:

"false" is truthy

Set DEBUG=false and your debug code still runs, because a non-empty string is truthy in JavaScript. env-saaf parses real booleans.

"3000" + 1 = "30001"

Ports and numbers arrive as strings, so arithmetic silently becomes concatenation. env-saaf returns typed numbers and validated ports (1–65535).

Missing in production

A forgotten variable does not fail at startup — it fails on the first request that needs it. env-saaf refuses to boot and lists all problems in one error.

Quick start

One schema, one call. The result is a frozen object with correctly typed values.

const { validateEnv } = require('env-saaf');

const env = validateEnv({
  PORT:      { type: 'port', required: true },
  DEBUG:     { type: 'boolean', default: false },
  API_URL:   { type: 'url', required: true },
  LOG_LEVEL: { type: 'string', choices: ['info', 'warn', 'error'], default: 'info' },
});

// env.PORT is a number · env.DEBUG is a real boolean
// anything wrong? One EnvSaafError listing every problem.

Keep .env.example honest

Your code and your .env.example drift apart silently. The CLI catches it — made for CI.

npx env-saaf scan ./src

Lists every env var your code actually uses — dot access, bracket access and destructuring.

npx env-saaf check .

Diffs code usage against .env.example. Exit code 1 if anything used is undocumented.

npx env-saaf example ./src

Drafts a fresh .env.example straight from a code scan.

maskSecrets(process.env)

Log your config safely — secrets print masked (sk***56), never in full.
